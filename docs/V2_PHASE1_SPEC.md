# SaaSGuide V2 Phase 1 短规格：XLSX 项目任务导入

## 阶段边界

本阶段只完成 XLSX 文件到统一项目 JSON 的本地闭环。它不接入 LLM、RAG、数据库、语音、PDF/OCR、真实 Jira 或其他企业系统，也不运行风险扫描。

项目仍是个人学习 Demo，使用虚构 SaaS、自建字段规则和模拟数据。

## 完成后的页面形态

新增独立页面 `Data Sources（数据源）`，保留现有 V1 风险看板入口。页面从上到下包含：

1. XLSX 文件选择区：说明只支持 `.xlsx`，限制 2 MB、1 个工作表、1000 条数据行。
2. Column Mapping（列映射）区：显示源列名，并为统一字段给出自动建议；用户可以修改。
3. Validation（校验）与预览区：显示前 20 行标准化预览，以及准确的行号、字段和错误原因。
4. 人工确认区：没有错误时才允许“确认导入”。
5. 导入结果区：显示项目、任务、依赖、来源文件、哈希和保存位置摘要。

## 文件流

```text
用户选择 XLSX
→ /api/imports/preview 检查文件并创建临时预览
→ 自动建议列映射
→ /api/imports/validate 按当前映射校验并返回预览
→ 用户确认
→ /api/imports/confirm 再次校验
→ data/raw/ 保存原始文件副本
→ data/normalized/ 保存统一 JSON
→ 页面显示导入摘要
```

`generated/imports/pending/` 只存放待确认临时文件，属于运行产物，不进入 Git。正式保存前会重新读取文件并再次校验，不能用旧的页面预览绕过服务器检查。

## 输入工作表

第一行必须是唯一且非空的列名。第一阶段只读取第一个可见工作表。

必须映射的统一字段：

- `project_id`：项目编号。
- `project_name`：项目名称。
- `task_id`：任务编号。
- `task_name`：任务名称。
- `owner`：负责人。
- `start_date`：开始日期。
- `due_date`：截止日期。
- `status`：任务状态。

可选字段：

- `priority`：优先级。
- `dependency_ids`：前置任务编号，多个编号用英文逗号、中文逗号或分号分隔。
- `progress_percent`：完成百分比，接受 0–100 或 Excel 百分比数值 0–1。
- `effort_hours`：工作量小时数。
- `update_text`：最新进展。
- `updated_at`：更新时间。

页面支持常见中英文列名自动映射；自动建议不是最终事实，用户仍可修改后重新校验。

## 统一 JSON

```json
{
  "schema_version": "2.0-phase1",
  "import_id": "import-...",
  "source": {
    "source_id": "source-...",
    "source_type": "xlsx",
    "source_name": "项目任务.xlsx",
    "source_version": "v1",
    "sha256": "...",
    "sheet_name": "项目任务",
    "imported_at": "2026-09-04T12:00:00+08:00"
  },
  "project": {
    "project_id": "project-001",
    "project_name": "星云 CRM 升级项目"
  },
  "tasks": [],
  "dependencies": [],
  "updates": [],
  "summary": {}
}
```

每条任务保留 `source_row`，使页面或后续规则能返回原工作表行号。原始 XLSX 不被模型结果覆盖。

## 校验规则

- 文件扩展名必须为 `.xlsx`，大小大于 0 且不超过 2 MB。
- XLSX 压缩包条目不超过 1000 个，解压后总大小不超过 20 MB。
- 只允许一个可见工作表；隐藏辅助表不读取。
- 数据行不超过 1000，列不超过 100。
- 标题不能为空或重复；必填统一字段必须全部映射；一个源列不能映射到多个统一字段。
- 项目编号和项目名称在同一文件内必须一致。
- 任务编号必须唯一；负责人不能为空。
- 日期必须可解析，截止日期不得早于开始日期。
- 状态只允许：未开始、进行中、阻塞、已完成、已取消。
- 完成百分比必须在 0–100；工作量不能为负数。
- 前置任务必须存在，且不能指向自己。
- 公式单元格不执行；当前阶段发现公式即停止并要求先转换为值。
- 空白行忽略；完全空的数据集拒绝导入。

## 模拟样本与标准答案

- `valid_project_tasks_cn.xlsx`：中文列名，6 条有效任务，含任务依赖和进展。
- `invalid_missing_owner.xlsx`：第 4 行负责人缺失。
- `invalid_dates.xlsx`：包含非法日期和截止日期早于开始日期。
- `invalid_dependencies.xlsx`：包含重复任务编号、自依赖和不存在的前置任务。
- `data/evaluation/phase1_expected_results.json`：记录每个样本预期的是否通过、任务数和错误代码。

## 验收条件

- 上述有效样本可完成预览、映射、确认和 JSON 保存。
- 三类错误样本均被服务器阻止，页面显示对应行号和原因，且不保存正式文件。
- 自动测试覆盖文件限制、别名映射、日期、状态、百分比、重复任务、依赖、确认时重检和原始文件哈希。
- 现有 38 项 V1 测试继续通过。
- Chrome 桌面与 390 × 844 页面真实验收通过，并记录控制台和页面级横向溢出结果。

只有以上条件实际通过后，Phase 1 才能标记完成；否则必须保留为“已实现但未完全验收”或“测试失败”。
