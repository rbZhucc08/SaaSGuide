# SaaSGuide V2-P2 短规格：确定性风险扫描

## 阶段边界

本阶段只对 V2-P1 的统一项目 JSON 运行 Python 确定性规则，输出带原始字段证据的候选风险，并保存人工决策记录。它不调用模型，不接入 RAG、数据库、语音、PDF/OCR 或真实外部系统。

候选风险不是正式风险。规则命中表示“值得人工检查”，不表示风险事实已经成立。

## 完成后的页面形态

新增 `Risk Radar（风险雷达）` 页面 `/risk-radar`：

1. 选择固定评测样本，或扫描 V2-P1 最近确认的统一 JSON。
2. 显示扫描日期、候选数量、规则命中和评测指标。
3. 每张候选卡显示任务、风险类型、等级、触发规则、原始字段值和源表行号。
4. 用户可以选择“确认、观察、驳回、标记误报”，但页面不会自动修改 V1 风险或任务。
5. 人工选择追加到本地 JSONL 审计记录；不覆盖原始导入文件。

## 第一批规则

| 规则 | 条件 | 输出类型 |
|---|---|---|
| `overdue_incomplete` | 截止日期早于扫描日，状态不是已完成或已取消 | `schedule_delay` |
| `overdue_low_progress` | 已逾期且完成度低于 80% | 与上条合并为同一 `schedule_delay` 候选 |
| `blocked_task` | 状态为阻塞 | `delivery_blocked` |
| `due_soon_low_progress` | 0–3 天内到期且完成度低于 50% | `schedule_pressure` |
| `direct_blocked_dependency` | 当前任务的直接前置任务处于阻塞 | `dependency_risk` |

去重键为“项目 + 任务 + 风险类型”。同一对象被多条规则命中时合并规则与证据，不重复生成候选。

## 固定评测集

- `data/evaluation/phase2_project_timeline.json`：固定扫描日和模拟项目任务。
- `data/evaluation/phase2_expected_results.json`：人工编写的正例、负例及理由。
- 评测输出：TP、FP、FN、Precision、Recall、False Positive Rate 和未评审候选。标准答案未标注的新候选不会被擅自判为误报。

评测故意保留一个误报和一个漏报，用于证明指标计算及规则边界，而不是追求虚假的 100%。

## 人工决策边界

- 允许：确认、观察、驳回、标记误报和填写不超过 500 字的说明。
- 保存：`generated/risk-decisions.jsonl`，记录候选 ID、选择、时间和来源标识。
- 不允许：规则自动改变等级、负责人、截止日期、任务状态，或写入 V1 `risk-data.json`。

## 验收条件

- 固定样本产生稳定候选，并与标准答案计算出可复现指标。
- 重叠规则正确去重，候选保留全部触发规则和源行证据。
- 最终状态任务不触发逾期规则，日期和结构异常明确停止。
- 最近 V2-P1 统一 JSON 可以被扫描；没有导入结果时返回可理解错误。
- 四种人工选择均可记录，非法选择和超长说明被拒绝。
- V1 与 V2-P1 现有测试无回归失败。
- Chrome 桌面和 390 × 844 页面完成候选、证据、指标和人工选择验收。
