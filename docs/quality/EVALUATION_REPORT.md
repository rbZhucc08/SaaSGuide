# 评测说明

## 为什么需要两类评测

SaaSGuide 同时包含确定性规则和 DeepSeek。两者不能共用一个“准确率”概念：

- 规则评测检查程序是否命中作者定义的风险标签；
- 模型评测检查 ASK/PLAN、引用和行动结构是否合格；
- 当前只有规则完成了 30 项批量基准；
- DeepSeek 只完成少量真实浏览器验收，没有批量模型得分。

## 单项目固定夹具

V2-P2 使用一份固定项目时间线：

- TP=5；
- FP=1；
- FN=1；
- Precision=83.33%；
- Recall=83.33%。

它用于验证评测函数本身和最小规则边界。样本太小，不能用于比较模型或宣传能力。

## 跨公司规则基准

### 数据

- 6 家虚构公司；
- 6 个行业；
- 30 个项目；
- 180 条任务；
- 固定扫描日 `2026-09-08`；
- 标准答案位于 `data/evaluation/company_scenario_expected.json`。

标准答案由模拟场景作者依据任务状态、公司阈值和依赖关系生成，不是独立企业专家标注。

### 指标定义

- TP：规则命中标准答案中的正例；
- FP：规则命中明确列出的已知负例；
- FN：标准答案为正例但规则没有命中；
- Precision：`TP / (TP + FP)`；
- Recall：`TP / (TP + FN)`；
- 严重度一致率：已命中正例中，规则严重度与标准答案一致的比例。

没有标注的新候选不能擅自算作 FP。

### 固定结果

| 指标 | 结果 |
|---|---:|
| TP | 119 |
| FP | 4 |
| FN | 18 |
| Precision | 96.75% |
| Recall | 86.86% |
| 严重度一致率 | 100% |

### 已知缺口

- 4 个 FP：临期且进度偏低，但剩余工作量不超过 20 小时；当前规则没有使用工时判断；
- 18 个 FN：标准答案要求提示间接阻塞依赖，而当前规则只检查直接依赖；
- 严重度 100% 一致只说明当前命中正例与同源标注一致，不代表严重度设计已经通过企业验证。

## DeepSeek 验收

已有真实 API 浏览器证据：

- 两次递进 ASK；
- 一次合法 PLAN；
- PLAN 含三条当前允许引用、三条连续行动和 Skill trace；
- Python 校验阻断非法结构和伪造引用；
- 验收未点击人工确认。

跨公司标准答案中还有 6 个预期 ASK 和 24 个预期 PLAN，但本轮没有批量调用 DeepSeek，`deepseek_runs=0`。这些预期不能当作实际模型结果。

## 不能从评测推出什么

- 不能把 96.75% 写成 DeepSeek 准确率；
- 不能把规则基准写成真实企业风险识别率；
- 不能用同源模拟标注证明跨行业泛化；
- 不能用一次 PLAN 证明模型长期稳定；
- 不能把结构校验通过解释为业务建议正确。

## 更可信的下一步

1. 让没有参与场景生成的人独立标注；
2. 预先写明标签口径和冲突处理；
3. 按公司或时间建立留出集；
4. 分开评估规则、检索、模型输出和人工采用；
5. 批量调用模型前设置费用上限、去标识化和重试规则；
6. 保留每次模型、提示词、输入版本和人工复核结果。
