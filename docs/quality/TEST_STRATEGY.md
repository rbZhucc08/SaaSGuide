# 测试策略

## 目的

测试不是为了证明系统“不会出错”，而是确认当前约定的输入、状态和安全边界没有被改坏。浏览器布局、真实文件选择和外部模型行为不能只靠单元测试推断。

## 自动检查入口

```powershell
& '.\run_checks.ps1'
```

该脚本执行：

1. 全部 Python unittest；
2. 关键模块语句覆盖率和类型契约检查；
3. Git 跟踪文件启发式密钥扫描；
4. `guide-data.json`、`risk-data.json` 与页面目标校验；
5. Markdown 本地链接检查；
6. 各前端 JavaScript 文件的 Node.js 语法检查；
7. `git diff --check`。

GitHub Actions 使用 Windows runner 创建 `.venv`、安装依赖并运行同一个脚本，避免本地和 CI 使用两套命令。

## 测试层级

| 层级 | 主要内容 | 不能替代什么 |
|---|---|---|
| 单元测试 | 字段、日期、规则、状态机、输出校验、指标 | 浏览器布局和真实外部服务 |
| API 集成测试 | Flask 请求、错误码、保存边界、安全响应头 | 人工文件选择和视觉体验 |
| 固定评测 | 规则 TP/FP/FN、检索引用和已知边界 | 真实企业准确率 |
| 浏览器验收 | 页面状态、操作结果、响应式布局、控制台 | 其他浏览器和长期稳定性 |
| 真实 API 验收 | DeepSeek ASK/PLAN、引用和结构 | 模型长期泛化和 SLA |
| 人工检查 | 本地文件选择、文档和截图一致性 | 自动回归能力 |

## 重点回归边界

- 模拟 Seed 不进入首页确认记录；
- 清空数据后不会自动恢复；
- 恢复数据必须显式触发；
- XLSX 不存在的列和错误依赖被阻断；
- 候选规则按项目、任务和风险类型去重；
- 固定评测不读取用户运行数据；
- DeepSeek API 密钥不返回浏览器；
- 伪造引用和非法 PLAN 被拒绝；
- 未经人工确认不创建行动；
- 报告只读取当前运行记录；
- 已退出产品的 `/v2` 路由继续返回 404；
- 所有功能页面保留完整导航和公共视觉壳。
- 真实数据安全闸门在生产能力缺失时保持阻断；
- 飞书缺少凭据时不允许同步，也不暴露凭据值；
- 飞书写回必须显式配置独立行动表；读写同表、未人工确认、缺任务编号或缺制度依据时不发出写回请求；
- 未授权或包含身份字段的试点记录不能进入业务验证统计。

## 当前覆盖

截至 2026-09-16 共 217 项自动测试，关键模块语句覆盖率为 89.04%，覆盖：

- V1 兼容数据和历史风险助手；
- XLSX、文本、DOCX、PDF 和 WAV 边界；
- 风险规则和人工决策；
- 知识检索和引用；
- SQLite 行动状态；
- 报告和导出；
- 模拟适配器；
- Agent 编排；
- 多公司数据；
- 跨公司固定基准；
- 页面路由、安全头和关键 DOM/API 合约。
- V3 双人工闸门与可追溯报告；
- 独立评测框架与盲标边界；
- 模型超时、重试、预算和错误分类；
- 混合检索、版本冲突与提示词注入防护；
- 安全治理、飞书读同步与人工确认写回连接器，以及真实试点证据校验。

## 浏览器范围

主要页面完成过桌面和 390 × 844 响应式矩阵验收。部分早期阶段因控制通道限制只取得应用内 Chromium 证据；每条验收记录会单独说明实际浏览器和未验证部分。

## 新增功能的最低要求

1. 正常路径测试；
2. 至少一个无效输入或失败路径；
3. 人工确认或数据边界不被绕过；
4. 页面可见状态与 API 返回一致；
5. 更新 PRD、功能说明和已知限制；
6. 运行完整检查而不是只运行新增测试；
7. 记录浏览器实际验收范围。
