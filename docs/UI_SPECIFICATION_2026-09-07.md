# SaaSGuide V2 UI Specification

更新日期：2026-09-07。

## 目标与边界

本轮只提升现有 SaaSGuide V2 的视觉层级、状态辨识、响应式效率和可访问性。保留现有路由、API 请求与响应字段、DOM ID、表单字段、XLSX 开放文本映射、DeepSeek ASK/PLAN、引用白名单、最多 3 条行动、Skill trace 和人工确认闸门。

本轮不新增 Agent、向量 RAG、OCR、语音、外部连接器、企业权限或商业结果。页面中的模拟数据、本地开发、未配置能力和人工确认限制继续如实显示。

## 视觉方向

定位为“克制、可信、可追溯的 AI 项目风险工作台”。视觉重点是信息层级和状态语义，不使用强发光、粒子、持续动画、大面积图片或营销落地页式装饰。

## 设计 tokens

### 色彩

- Canvas：`#f3f5fa`，应用背景。
- Surface：`#ffffff`，主要卡片。
- Surface subtle：`#f8f9fc`，次级分组与表头。
- Ink：`#111a2e`，标题和关键数字。
- Muted：`#647089`，说明文字。
- Line：`#dfe5ef`，结构边界。
- Brand：`#6157e7`；hover `#4d43cf`；soft `#efedff`。
- Success：`#14805e`；soft `#e8f7f1`。
- Warning：`#a86408`；soft `#fff4dc`。
- Danger：`#c93850`；soft `#fff0f3`。
- Info：`#3168c6`；soft `#eef5ff`。
- Sidebar：`#191d33`；active `#363553`。

所有状态必须同时有文字或图形标识，不能只依赖颜色。

### 字体

- 字体栈：Segoe UI、Microsoft YaHei、系统无衬线。
- 页面标题：32px / 1.2 / 750；手机 28px。
- 二级标题：18px / 1.35 / 700。
- 正文：14px / 1.7 / 400。
- 辅助文字：12px / 1.6 / 400。
- 数据数字：28–32px / 1.05 / 750，使用等宽数字特性。

### 间距、圆角和阴影

- 以 4px 为最小单位，常用间距为 8、12、16、24、32px。
- 控件圆角 10px；卡片圆角 16px；关键面板圆角 18px；胶囊状态 999px。
- 主卡片使用一层低对比阴影；hover 只增加轻微边框/阴影，不位移重要操作。
- 桌面内容最大宽度 1440px；左侧栏 232px。

## 公共组件

- App Shell：固定语义侧栏与浅色画布；不改变八项导航及路由。
- Page Header：eyebrow、标题、摘要、页面级操作四层结构。
- Card / Panel：统一内边距、圆角、边框和标题间距。
- Metric Card：图形、口径、数字、补充说明四层结构。
- Button：主按钮只用于页面当前关键动作；次按钮用于导航、重试和辅助动作。
- Form Field：label、输入、帮助/错误文本明确关联；保留原始 `name` 和 DOM ID。
- Status Badge：AI 可用性、风险等级、校验结果、能力限制使用不同语义色。
- Message：info、success、warning、error 具有不同边框和背景；保留 `aria-live`。
- Table：表头固定浅底色，单元格允许长文本换行；手机端在局部容器横向滚动，禁止页面级横向滚动。
- Disclosure：Skill trace 默认折叠，展开后显示纵向步骤线和 completed/failed 状态。

## 交互状态

- Focus：所有链接、按钮、输入和 summary 使用 3px 可见焦点环。
- Hover：150ms；背景、边框或阴影轻微变化。
- Loading：按钮保留原宽度，显示进行中动词并禁用。
- Disabled：降低对比但仍可读，不移除控件。
- Error：说明发生了什么以及下一步，不清空用户已填映射。
- Reduced motion：`prefers-reduced-motion: reduce` 下取消非必要过渡和滚动动画。

## 响应式

- Desktop：`> 1100px`，侧栏 + 内容双栏。
- Compact desktop / tablet：`701–1100px`，内容栅格降列，侧栏保持可用。
- Mobile：`<= 700px`，侧栏变为顶部区域，导航可横向滚动；页面内容单列。
- Small mobile：`<= 420px`，指标和表单单列，操作按钮尽量整行。
- 验收视口：1440×900、872px 宽、768px 宽、390×844。

## 三个代表页面

### `/` 概览

- 页面头部突出真实更新时间和两项明确入口。
- 四个指标使用一致的图形、口径、数字和说明，不制造无数据样板。
- 最近活动是主内容；下一步作为右侧决策面板，说明人工/本地边界。
- 空状态只给一个下一步，不添加虚构趋势图。

### `/risk-radar`

- 扫描入口作为“确定性规则”起点，AI 状态独立显示。
- 候选卡顺序固定为：风险标题与等级 → 规则依据 → 原始证据 → AI 草稿 → 人工决策。
- ASK 使用蓝色问题区；PLAN 使用紫色草稿区，并分为判断、行动、注意事项和引用。
- 引用仅展示响应中属于 `citationIds` 白名单的内容。
- Skill trace 默认折叠，展开后为运行时间线。
- 人工决策区使用中性背景；确认、观察、驳回和误报仍是四个独立动作。

### `/data-sources`

- 上传卡展示四步流程语义，但不新增后端流程。
- 文件上传与内置样本明确分隔，避免把样本路径误解为真实上传。
- 列映射继续用自由文本 input + datalist；必填、建议和错误更清楚。
- 校验摘要、错误列表、表格预览和确认区域有明确视觉顺序。
- 手机端映射单列；表格只在自身容器滚动。

## 验收口径

- 视觉提升：层级、排版、组件、响应式、焦点和状态辨识。
- 真实工程提升：新增 UI 契约回归、浏览器状态覆盖和验收记录。
- 仅计划能力：Agent、向量 RAG、OCR、语音、外部连接器、企业部署与业务成果；本轮均不实现。
