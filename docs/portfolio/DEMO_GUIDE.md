# SaaSGuide V3 演示路线

这份路线适合 4–6 分钟现场演示。重点展示一条可追溯业务链和一个真实限制，不逐页朗读功能。

## 演示前准备

1. 按 README 启动服务并打开 `http://127.0.0.1:4173/`；
2. 使用仓库内模拟数据，不上传真实公司文件；
3. 如演示 DeepSeek，提前配置本机环境变量，并准备模型不可用时的解释；
4. 不展示 API 密钥、个人信息、运行日志或未去标识化数据；
5. 先运行 `run_checks.ps1`，确认当前结果仍是 186 项通过。

## 0:00–0:35：一句话说明

> SaaSGuide 是一个本地运行的项目风险 AI 应用个人项目。程序先从任务事实中发现候选风险，DeepSeek 在当前制度范围内提出追问或行动草稿，最后由人分别确认风险和行动。

指出首页只汇总确认后的本地记录，模拟 Seed 不会被伪装成用户运行结果。

## 0:35–1:15：查看数据与安全边界

进入“数据源”，选择企业软件或制造业模拟公司：

- 展示项目、任务、制度和公司风险阈值；
- 说明 XLSX 需要字段映射、校验和人工确认；
- 指出真实数据安全状态仍为阻断；
- 简要展示飞书多维表格只读连接器的“真实授权待完成”，不要声称已经同步。

## 1:15–2:20：扫描候选风险

进入“风险雷达”：

1. 选择项目并运行确定性扫描；
2. 展开一条候选，指出来源任务、命中字段和规则；
3. 强调候选只是提示，仍需人工判断；
4. 展示制度引用来自当前公司和当前有效版本。

## 2:20–3:25：解释 ASK / PLAN 与双闸门

如 DeepSeek 可用，发起一次研判；不可用时使用历史验收记录解释，不把历史结果说成现场结果。

- ASK 表示信息不足，需要补充问题；
- PLAN 是带引用的行动草稿；
- Python 会拒绝非法 JSON、伪造引用、超过三条行动和缺少负责人或完成信号；
- 风险确认和行动确认是两个步骤，模型不能直接落库。

## 3:25–4:10：展示评测而不夸大

展开开发评测：

- TP=119、FP=4、FN=18；
- Precision=96.75%、Recall=86.86%；
- 说明这是作者构造并标注的 30 个合成项目，只用于回归；
- 当前外部盲标为 0/2，DeepSeek 没有批量运行这些项目。

## 4:10–4:55：展示行动与工程证据

- 展示 PLAN 只能预填行动，仍需人确认；
- 展示行动事件审计和报告来源；
- 打开 `run_checks.ps1`、V3 证据索引和阶段记录；
- 说明全新虚拟环境已按锁定依赖完成 186 项测试。

## 4:55–5:30：以真实限制收尾

打开“业务验证”页面：

> 当前研究协议和分析工具已经准备好，但真实参与者仍是 0。飞书也没有真实授权，项目没有生产权限和公开部署。因此它证明的是一条受约束、可测试、可追溯的 AI 应用流程，不证明企业采用或商业收益。

## 不要这样演示

- 不说“训练了 DeepSeek”；
- 不说“使用 LangChain、LangGraph 或企业级多 Agent”；
- 不把规则 Precision 称为模型准确率；
- 不说已经接入真实飞书；
- 不把稀疏词频向量称为向量数据库；
- 不把阶段 11 的工具说成真实用户验证；
- 不为了让首页好看而制造运行记录。
