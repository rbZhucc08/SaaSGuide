# 演示路线

这份路线适合 4–6 分钟现场演示。不要逐页介绍所有功能，重点展示一条完整链路和一个真实边界。

## 演示前准备

1. 按 README 启动服务；
2. 确认首页地址为 `http://127.0.0.1:4173/`；
3. 如果演示 DeepSeek，提前在进程环境变量中配置密钥；
4. 使用仓库内模拟数据，不上传真实公司文件；
5. 不提前制造虚假的“企业运行记录”。

## 0:00–0:40：说明项目

建议直接说：

> 这是一个本地运行的项目风险管理学习项目。它先用程序发现候选风险，再让 DeepSeek 在当前制度范围内给出 ASK 或 PLAN，最后由人确认。所有公司和业务数据都是模拟内容。

在首页指出：当前数字只来自确认后的本地运行记录，固定样本不会混入首页。

## 0:40–1:30：查看公司差异

进入“数据源”：

1. 展示 6 家公司、6 个行业、30 个项目和 48 个制度版本；
2. 切换跨境电商和制造公司；
3. 指出两者项目名称、经营特征和风险阈值不同；
4. 说明这是上下文工程和模拟数据设计，不是模型训练。

## 1:30–2:40：扫描候选风险

选择一个项目进入风险雷达：

1. 运行所选项目扫描；
2. 展示候选风险类型和严重度；
3. 展开原始证据和触发规则；
4. 说明候选只是提示，不是已经确认的事实。

## 2:40–3:50：演示 ASK/PLAN

如果 DeepSeek 已配置：

1. 选择一条候选并请求 AI 研判；
2. 若返回 ASK，解释缺失信息并补充；
3. 若返回 PLAN，核对行动、完成信号和制度引用；
4. 展开 Skill 运行轨迹；
5. 强调 Python 会阻断伪造引用和不合格结构；
6. 不点击正式确认，说明模型不能替用户落库。

模型输出具有不确定性。现场结果如果与历史验收不同，应如实展示，不要把历史结果说成当前必然结果。

## 3:50–4:40：展示评测

展开“开发评测”，运行跨公司基准：

- TP=119、FP=4、FN=18；
- Precision=96.75%、Recall=86.86%；
- 6 家公司分组；
- DeepSeek 实际运行 0 次。

解释其中 4 个误报和 18 个漏报是如何设计出来的，并指出标准答案与模拟数据同源，所以不能称为真实准确率。

## 4:40–5:20：展示工程证据

打开仓库：

- 展示 `run_checks.ps1` 和 135 项测试；
- 展示 Agent 工作流图；
- 展示验收记录和已知限制；
- 说明密钥、用户导入、SQLite 和日志不会进入 Git。

## 结束语

> 这个项目主要证明的是：我能把数据校验、业务规则、模型调用、引用约束、人工确认和评测组织成一条可验证的 AI 应用流程。它还没有真实企业接入和生产部署，所以我不会用它宣称商业效果。

## 不要这样演示

- 不说“训练了 DeepSeek”；
- 不说“企业级多 Agent”；
- 不把固定评测称为模型准确率；
- 不为了让首页好看而预填虚假运行结果；
- 不现场展示或复制 API 密钥；
- 不上传个人简历、真实客户文件或公司内部资料。
