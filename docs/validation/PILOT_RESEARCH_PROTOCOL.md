# SaaSGuide 小规模真实试点研究协议

## 研究问题

目标用户在审查一个延期风险并决定后续行动时，是否能理解规则证据、制度引用和 AI 草稿？哪些建议会被接受、修改或拒绝，原因是什么？

## 参与者与数据

- 目标角色：日常需要跟踪项目任务、风险或行动的项目负责人或运营协同人员；
- 参与前说明这是个人学习 Demo，AI 输出仅为草稿；
- 取得明确参与同意和数据使用授权；
- 使用模拟项目，或经授权且去标识化的真实任务片段；
- 不收集姓名、电话、邮箱、公司名、账号或客户信息；
- 原始访谈笔记保存在项目目录外，结构化编码后才可进入本地分析文件。

## 流程

1. 不使用 SaaSGuide 完成一次相同范围的风险审查，记录任务耗时和主要步骤；
2. 简短介绍数据、规则、制度引用、AI 草稿和人工双闸门；
3. 使用 SaaSGuide 完成同一类任务，记录耗时、阻塞和错误；
4. 对每条系统建议记录接受、修改或拒绝，并选择编码原因；
5. 进行访谈，重点追问证据可信度、理解成本和不愿采用的原因；
6. 去标识化并复核结构化记录，再运行分析工具。

## 停止与排除

发现个人信息、商业秘密、未授权客户数据或参与者不愿继续时立即停止。不得以模拟访谈、Codex 扮演用户或研究者自行填写结果替代真实参与者。

## 解读限制

任务先后顺序、学习效应、样本选择和研究者在场都会造成偏差。任务耗时差异只是观察值，不构成因果效果；建议接受率也不等于建议正确率。
