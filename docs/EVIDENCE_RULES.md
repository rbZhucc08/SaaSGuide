# 实现与验证证据规则

## 状态词的含义

| 状态 | 必须具备的证据 | 不能推导的结论 |
|---|---|---|
| 仅计划 | 规格或路线图 | 功能存在、可以运行 |
| 已实现 | 代码和可识别入口 | 测试通过、用户可正常使用 |
| 自动测试通过 | 实际命令、测试数量和结果 | 浏览器布局、真实文件选择、生产稳定性 |
| 浏览器验证通过 | 浏览器、页面、尺寸、操作和可见结果 | 其他浏览器、其他系统、长期稳定性 |
| 人工验证 | 操作者、动作和观察范围 | 自动可复现、未观察结果也正确 |
| 阶段完成 | 阶段规格中的验收条件均有对应证据，且限制已记录 | 后续阶段能力、企业级或生产级能力 |

## V2-P1 的证据组合

- 单元与接口测试证明解析、映射、校验、确认重检和保存逻辑。
- Chrome 内置样本证明页面能呈现相同 XLSX 内容的映射、错误、禁用和成功状态。
- 用户人工操作证明本机 Chrome 的文件选择器可选择两份本地 XLSX 并触发预览。
- 文件系统核对证明确认后生成原件副本和标准化 JSON，且 SHA-256 一致。

这些证据互补但不可互相冒充。特别是内置样本浏览器闭环不等于浏览器自动上传；人工完成文件选择也不等于所有预览结果都由自动化捕获。

## 求职与公开表述

只能陈述已经实现、运行并有证据支持的部分。必须保留“个人学习 Demo、虚构 SaaS、自建规则、模拟数据、无真实企业接入和业务效果”的限定。路线图中的 RAG、数据库、Agent、OCR、部署和真实外部连接器不得提前进入简历。
