# V3 阶段 3：完整业务闭环规格

## 目标

把候选风险、人工风险决策、AI PLAN 草稿、人工行动确认、状态事件和报告汇总连接为可回溯链路。

## 数据关系

```text
scan_id → candidate_id → decision_id → action_id → action_event_id
                       ↘ plan_run_id / plan_step ↗
```

- 扫描批次由来源、项目、扫描日和规则版本确定；
- 候选保留公司、项目、任务、来源、扫描批次、规则证据和制度引用；
- 行动必须绑定当前最新的“确认”风险决策；
- PLAN 可预填 1–3 条行动草稿，但不会填写期限、勾选人工确认或自动保存；
- 行动状态事件只追加，不覆盖历史；
- 报告对同一候选只读取最新人工决策，并返回可追溯 ID。

## 迁移与备份

数据库 Schema 从 v1 升到 v2。打开已有 v1 数据库时，迁移前自动生成同目录 `*.db.pre-v2.bak`，已有表和记录保留；新列通过增量 `ALTER TABLE` 加入。

手工备份步骤：停止本地服务，复制 `generated/saasguide-v2.db` 到项目外的安全目录，再启动服务。运行库和备份均受 `.gitignore` 排除。

## 非目标

- 不让 AI 自动确认风险或行动；
- 不把模型草稿作为正式行动；
- 不引入多用户权限、通知或外部平台写回；
- 不改变固定规则定义。

## 验收标准

- 缺少任一人工确认都无法创建行动；
- PLAN 预填保留 run ID 和步骤号；
- 完成、重开、撤销和非法转换有测试；
- 报告能返回候选、决策和行动 ID；
- 旧数据库迁移前产生备份；
- 自动测试和至少一条本地模拟项目浏览器链路通过。
