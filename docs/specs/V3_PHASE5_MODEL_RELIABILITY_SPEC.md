# V3 阶段 5：DeepSeek 稳定性与可观察性规格

日期：2026-09-09

## 目标

让 DeepSeek 请求的成功、失败、重试、输出拒绝和预算拦截可区分、可测试、可记录，同时保证模型不可用时确定性规则和人工确认路径继续工作。

## 非目标

- 不接入第二家模型供应商；
- 不批量调用真实 API；
- 不把 Token 估算写成供应商账单；
- 不承诺同一输入得到相同文本；
- 不把结构合法等同于业务建议正确。

## 协议与版本

- 供应商接口：`JsonModelProvider`；当前唯一实现为 `DeepSeekClient`；
- 客户端协议：`deepseek-json-v1`；
- 风险 Prompt：`risk-planner-prompt-v3.1`；
- ASK/PLAN 输出协议：`risk-ask-plan-v1`；
- 预算策略：`model-budget-v1`。

ASK 和 PLAN 顶层及嵌套对象只接受规定字段。PLAN 引用必须来自本次检索白名单，行动为 1–3 条连续步骤，每条都包含执行角色和完成信号。

## 稳定性边界

- 单次超时：20 秒；
- 最大重试：2 次，即最多尝试 3 次；
- 退避：0.25 秒起的有限指数退避；
- 只重试超时、网络不可用、HTTP 429、500 和 503；
- 鉴权、余额、请求参数和无效响应不重试。

错误分类：`timeout`、`rate_limited`、`provider_unavailable`、`invalid_auth`、`insufficient_balance`、`invalid_request`、`invalid_response`、`invalid_model_output`、`over_budget`。

## 预算

- 单次输入上限 8,000 Token（本地保守估算）；
- 单次输出上限 2,000 Token；
- 单次总上限 10,000 Token；
- 批量最多 10 次，预留总量最多 30,000 Token。

预算在请求发出前预留。供应商返回的实际总 Token 超限时拒绝结果。当前没有稳定、已核实的费用价目映射，因此运行记录中的费用为 `null`，并注明供应商未提供；不能据此声称真实成本为零。

## 可观察性与隐私

运行记录包含随机去敏运行 ID、供应商、模型、客户端协议、状态、错误分类、延迟、尝试次数、重试次数、可用 Token 字段和费用可用状态。API 密钥、完整 Prompt 和原始响应不写入遥测。

真实运行写入被 Git 忽略的 `generated/ai-runs.jsonl`。页面读取能力端点，展示配置状态、失败时的保底路径、超时、重试和单次预算。

## 完成闸门

- 合法 ASK、合法 PLAN、超时、限流、非法 JSON、伪造引用、超预算和供应商不可用均有自动测试；
- 页面能显示模型配置状态和运行边界；
- 失败响应保留明确错误分类和人工路径提示；
- 少量真实调用与模拟故障分开记录。
