# V3 阶段 4：独立评测框架规格

日期：2026-09-08

## 目标

建立一套可运行、可复核的盲标与组件评测流程，把确定性规则、知识检索、模型输出和人工判断分开。框架必须如实显示人工标注是否完成，不能用程序生成的答案替代独立标注者。

## 非目标

- 本阶段不生成或填写人工标签；
- 不声称模拟案例代表真实企业分布；
- 不在留出集上调规则或 Prompt；
- 不批量调用 DeepSeek；
- 不把结构校验通过等同于业务建议正确。

## 数据与流程

1. `development_blind.json` 和 `holdout_blind.json` 只提供案例事实与可用制度编号，不含预测或标准答案。
2. 两位未参与场景生成的标注者分别复制标注模板、使用不同匿名编号并覆盖全部案例。
3. 程序校验字段、枚举、覆盖范围和判断依据。
4. 程序逐字段计算一致率，列出分歧案例。
5. 有分歧时由第三方或双方复核后提供逐案例裁决；未裁决的分歧不能进入最终标签。
6. 最终标签与系统预测分开输入组件指标函数。

开发集允许用于发现规则、检索或 Prompt 的问题。留出集只在方案冻结后运行一次；若据此修改系统，必须建立新的留出集。

## 组件指标

- 规则：TP、FP、FN、Precision、Recall、F1；
- 检索：人工要求制度编号的平均召回；
- 引用：人工复核为“有支持”的比例；
- 模型：输出协议的结构合格率；
- 行动：人工复核为“可执行”的比例。

错误分类包含误报、漏报、引用错误、信息不足、建议不可执行和严重度不一致。指标缺少人工复核分母时返回空值，不自动补零。

## 页面和 API

`GET /api/evaluation/framework` 只报告框架状态、案例数量、预测字段检查、有效标注文件数和可计算指标。风险雷达的“开发评测”折叠区提供显式检查入口。

当前预期状态为：`独立评测框架完成，外部标注待完成`，标注者 `0/2`。

## 完成闸门

- 盲标包、模板、标注校验、一致性、裁决和组件指标均有自动测试；
- 页面能清楚显示开发集、留出集、预测字段和人工依赖；
- 自动测试、浏览器验收和记录完成；
- 不产生虚构的独立评测分数。
