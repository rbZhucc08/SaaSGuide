# SaaSGuide V3 产品需求文档

版本：3.0 Portfolio Candidate

日期：2026-09-09

状态：本地单用户作品集候选；外部验证待完成

## 1. 产品概述

SaaSGuide 用于整理项目风险信息。用户可以导入或维护项目任务，运行确定性规则得到候选风险，再让 DeepSeek 在当前公司制度范围内补充判断和行动草稿。所有正式记录都由人确认。

这是一个个人学习项目。公司、制度、项目和评测数据都是虚构内容，不对应真实企业。

## 2. 目标用户

主要用户是假设中的项目负责人、交付负责人或运营负责人。他需要：

- 从项目任务中发现可能逾期、阻塞或受依赖影响的事项；
- 查看候选判断所依据的原始字段；
- 依据当前有效制度复核风险；
- 把可执行行动交给明确角色并追踪状态；
- 区分程序规则、模型建议和人工结论。

## 3. 问题定义

### 3.1 数据分散

任务表、周报和制度文档的结构不同，无法直接形成统一的风险记录。

### 3.2 模型结论缺乏约束

直接让大模型阅读全部文本，会产生引用来源不明、输出结构不稳定和自动越权的风险。

### 3.3 结果难以追溯

如果不保留原始行、文档版本和人工选择，后续无法解释一个风险为什么出现，也无法区分候选和事实。

## 4. 产品目标

- 把项目、任务和证据整理成可校验的本地数据；
- 用可解释规则生成候选风险，而不是直接宣布事实；
- 只向模型提供当前公司画像、当前生效制度和允许引用的候选内容；
- 让模型在信息不足时 ASK，充分时输出 PLAN；
- 在保存正式行动前保留人工确认；
- 提供固定模拟评测，暴露误报、漏报和规则边界；
- 保留可复现的自动测试和浏览器验收记录。

## 5. 非目标

- 不训练或微调模型；
- 不实现生产级账号、权限、多租户和并发协作；
- 不自动替用户修改负责人、期限、风险状态或正式行动；
- 不接收真实商业敏感数据；
- 不把模拟评测解释成真实企业准确率；
- 不实现公开部署、真实 OCR、语音识别或第三方平台写回。

## 6. 核心场景

### 场景 A：维护公司项目

用户选择一家模拟公司，查看其业务背景、风险标准、项目、任务和制度；也可以新增、编辑或删除当前本地记录。

### 场景 B：导入项目任务

用户上传 XLSX，自行输入原始字段名或采用表头建议。程序预览映射、校验必填字段、日期和依赖，只有人工确认后才保存标准化数据。

### 场景 C：扫描候选风险

用户选择项目和扫描日期。程序根据当前公司阈值检查逾期、临期低进度、阻塞和直接依赖，并显示来源字段和触发规则。

### 场景 D：请求 AI 研判

用户在某条候选风险中调用 DeepSeek。Orchestrator 检索当前生效制度，模型返回 ASK 或 PLAN，程序再校验结构和引用。结果只显示为草稿。

### 场景 E：记录人工结论与行动

用户可以确认、观察、驳回或标记误报。创建行动时还需独立确认，SQLite 保存状态和事件记录；报告从这些本地记录计算。

### 场景 F：运行开发评测

用户在风险雷达展开“开发评测”，运行固定跨公司基准，查看总体和公司分组指标。评测不进入首页，也不自动调用 DeepSeek。

## 7. 功能需求

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-01 | 公司上下文切换 | 项目、制度、扫描和模型上下文只读取当前公司 |
| FR-02 | 公司与项目 CRUD | 页面操作跨刷新保留；清空与恢复必须明确触发 |
| FR-03 | XLSX 接入 | 映射可输入；不存在的列、错误日期和依赖被阻断 |
| FR-04 | 证据接入 | 保留文件哈希、原文位置和人工核对状态 |
| FR-05 | 确定性扫描 | 候选包含风险类型、严重度、触发规则和证据 |
| FR-06 | 知识检索 | 只返回当前有效版本；无依据时拒答 |
| FR-07 | DeepSeek ASK/PLAN | 信息不足返回 ASK；PLAN 引用和行动结构必须合格 |
| FR-08 | 人工决策 | AI 不能绕过确认写入正式行动或修改正式状态 |
| FR-09 | 行动审计 | 保存行动、状态转换和追加式事件 |
| FR-10 | 报告输出 | 从当前本地记录计算，并导出 CSV/XLSX |
| FR-11 | 固定评测 | 使用版本化 Seed；不读取用户运行副本；显示指标边界 |
| FR-12 | 飞书只读接入 | 缺少授权时阻断；分页读取、本地幂等合并且不写回 |
| FR-13 | 真实试点状态 | 没有真实参与者和授权数据时保持外部证据待完成 |

## 8. 状态与权限规则

- 候选风险不是事实；
- AI PLAN 不是人工结论；
- 人工风险决策和正式行动是不同记录；
- 未勾选人工确认时，不创建行动；
- 模型无权修改任务负责人、截止日期和风险状态；
- 运行数据只保存在本机，当前没有用户账号或角色权限。

## 9. 数据要求

- Seed 与用户运行副本分开；
- 原始导入与标准化 JSON 分开；
- 标准化任务保留来源文件、哈希和源行；
- 制度包含文档编号、版本、生效日期和状态；
- SQLite 记录行动与状态事件；
- Git 忽略用户导入、运行数据库、日志、密钥和备份。

## 10. 成功标准

本项目不使用商业指标作为成功标准。发布验收使用工程证据：

- 新环境可按 README 启动；
- 自动检查全部通过；
- 核心页面和主要状态完成浏览器验收；
- 非法模型输出、伪造引用和未确认行动被阻断；
- 固定评测结果可复现；
- README、架构、操作、证据、安全和限制文档一致。

## 11. 当前结果

- 186 项自动测试通过，关键模块语句覆盖率 89.04%；
- 6 家公司、30 个项目、180 条任务、48 个制度版本；
- 固定规则基准 TP=119、FP=4、FN=18；
- 真实 DeepSeek 验收得到两次 ASK 和一次 PLAN；
- 所有结果仅证明当前模拟输入和本地环境中的行为。

## 12. 后续选项

后续不是当前版本的完成条件：

- 建立独立人工标注的留出评测集；
- 接入一个真实但去标识化的数据源；
- 增加账号、权限和生产部署设计；
- 在预算和隐私边界明确后批量评测模型 ASK/PLAN；
- 增加真实 OCR 或语音能力；
- 在最小权限下完成飞书真实只读授权验收；
- 使用授权且去标识化的数据开展真实小规模试点。
