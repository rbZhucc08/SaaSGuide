# 用户手册

## 1. 启动

在项目根目录执行：

```powershell
& '.\start_v2.ps1'
```

然后打开 `http://127.0.0.1:4173/`。如果提示缺少 `.venv`，按仓库首页先创建虚拟环境并安装依赖。

## 2. 使用模拟公司数据

1. 进入“数据源”；
2. 在“多公司项目档案”选择公司；
3. 查看该公司的经营特征、风险标准和项目；
4. 点击项目旁的“扫描”，进入风险雷达；
5. 如已修改或清空数据，可点击“恢复多公司数据集”。

恢复会用版本化 Seed 覆盖本地模拟公司数据，应只在确认需要重置时操作。

## 3. 导入 XLSX

1. 在“数据源”选择 `.xlsx` 文件；
2. 点击“生成预览”；
3. 检查程序识别出的表头；
4. 在映射框输入原表中的实际列名，或采用建议；
5. 查看前 20 行预览和错误信息；
6. 只有确认无误后才保存。

常见错误：

- “列不存在”：映射文字没有与原表头完全一致；
- “日期无效”：日期无法转换为 `YYYY-MM-DD`；
- “依赖不存在”：任务引用了表中没有的任务编号；
- “缺少负责人”：必填字段为空。

## 4. 扫描风险

1. 进入“风险雷达”；
2. 选择当前公司项目；
3. 可选填扫描日期；
4. 点击“扫描所选项目”；
5. 阅读候选类型、严重度、触发规则和原始证据；
6. 根据实际判断选择确认、观察、驳回或误报。

候选不等于事实。确认风险决策也不会自动修改原任务。

## 5. 使用 DeepSeek

只有服务进程配置 `DEEPSEEK_API_KEY` 后，候选卡的 AI 研判才能调用模型。

1. 在候选卡点击 AI 研判；
2. 如果返回 ASK，补充页面要求的信息；
3. 如果返回 PLAN，核对建议、引用和行动；
4. 不要因为页面显示 PLAN 就直接当作正式结论；
5. 需要建立行动时，再到行动页面执行人工确认。

程序会阻断伪造引用、缺失字段、超过三条行动或步骤不连续的输出，但无法保证建议本身一定正确。

## 6. 管理知识

1. 进入“知识库”；
2. 检查当前公司；
3. 新增或编辑制度版本；
4. 设置生效日期和状态；
5. 用问题测试检索结果；
6. 核对回答引用的文档编号和版本。

没有依据时出现拒答是正常行为，不应为了得到回答而隐藏缺失信息。

## 7. 创建和更新行动

1. 先确认候选风险；
2. 进入“行动跟踪”；
3. 填写行动、负责人角色、截止日期和完成信号；
4. 勾选人工确认；
5. 创建后按允许路径更新状态；
6. 查看事件记录确认变化已保存。

未勾选确认时，接口会拒绝创建行动。

## 8. 查看报告

进入“报告”查看当前本地风险决策和行动。CSV/XLSX 下载只反映当前运行记录。页面为空时，说明还没有保存过确认记录，不是程序故障。

## 9. 运行固定评测

1. 进入“风险雷达”；
2. 展开“开发评测”；
3. 点击“运行跨公司基准”；
4. 查看总体指标和公司分组；
5. 注意页面中的“DeepSeek 未运行”和合成数据声明。

固定评测不读取你修改后的公司运行副本，也不会产生正式风险或模型费用。

## 10. 停止服务

回到启动服务的终端，按 `Ctrl+C`。本地运行数据保存在 `generated/`，该目录不会进入 Git。
